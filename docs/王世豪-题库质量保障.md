## 使用方法

以下命令在server目录、已安装后端依赖的Python环境中执行。报告路径必须不存在；输出父目录须已存在。

```bash
python scripts/audit_question_bank.py --snapshot data/demo_snapshot.json --output ../audit-new.json --markdown ../audit-new.md
python scripts/setup_team.py --database ../bank-check.db --actor "核验人"
python scripts/audit_question_bank.py --database ../bank-check.db --previous ../audit-new.json --output ../audit-db.json --markdown ../audit-db.md
```

数据库审计使用只读连接和一致性读事务，不做迁移、补字段或审批。运行中的数据库可能发生并发变化，检测到主文件/WAL变化会拒绝结果；归档审计建议针对稳定备份执行。原始文件哈希与事务内逻辑行哈希各有含义，报告分别标注。

退出码：0为没有确定性结构错误（不表示内容审核通过）；1为存在确定性结构错误；2为输入或输出错误。旧版final3报告不符合新版规则/格式，不能直接作为`--previous`；本轮重新建立基线。

人工处理文件可通过`--triage triage.json`附加，示例：

```json
{"issues":{"报告中实际的audit-ID":{"state":"in_progress","reviewer":"核验人","note":"记录证据与处理理由"}}}
```

状态允许open、in_progress、resolved、accepted_risk、false_positive、deferred。标注不删除发现，不改变数据库，不等于真实问题消失；报告diff中的resolved仅表示该稳定编号本轮不再出现。实际修复仍需通过现有版本/审核流程。
