## 1. 这次解决什么问题

我的职责是把真题 PDF 中的文章、句子、题目和答案整理成可入库的数据，并为题目提供可追溯的原文位置。这次优先修复已有导入链路的数据可靠性问题。

原流程存在三个关键风险：

1. 模型输出如果缺少某题或选项，程序可能跳过该题，再按列表顺序给剩余题目重新编号。这样会让后面的题目与答案发生错位。
2. 原文定位会使用关键词重合度，甚至在没有证据时选第一句或最长句，导致界面给出看似明确、实际不可靠的定位。
3. 答案来源主要出现在导入成功提示里，没有完整保存到数据库，刷新后难以区分用户提供的答案和模型推断的答案。

本次修改的原则是：先校验、按原题号对齐、无法确认时保留待复核状态，再一次性入库。

## 2. 已完成的修改

### 2.1 保留原卷题号，阻止答案错位

自动导入明确支持阅读理解 Part A 的 Text 1—4，每篇五题：

| Text | 原卷题号 |
| --- | --- |
| 1 | 21—25 |
| 2 | 26—30 |
| 3 | 31—35 |
| 4 | 36—40 |

- 提取结果必须保留原题号，不再把题目重编号为 1、2、3……。
- 校验题目数量、题号范围、重复题号、题干、四个选项以及答案格式。
- 缺题或缺选项时拒绝整篇导入，返回具体问题，不再跳过坏题后继续保存。
- 即使模型返回题目顺序打乱，也按原题号匹配答案，再排序保存。
- 手动录入单题仍使用自定义题目编号，不宣称还原了原卷题号。

答案输入支持以下三类格式（仅为格式示例，不是实际真题答案）：

```text
ABCDA
21-25 ABCDA
21:A,22:B,23:C,24:D,25:A
```

题号范围必须与当前 Text 对应；多余字符、缺少答案和重复题号都会报错。

### 2.2 保存答案来源和待复核状态

数据库新增：

| 字段 | 含义 |
| --- | --- |
| answer_source | provided 用户提供、inferred 模型推断、manual 手工录入、unknown 旧数据来源未知 |
| answer_source_note | 用户填写或系统生成的来源说明 |
| review_status | 新导入统一为 pending，表示尚未人工复核 |
| source_quote | 提取结果给出的原文引文 |
| location_status | 引文定位的结果状态 |

前端展示答案来源、来源说明和待复核提示，刷新后仍可从接口读取。

注意：用户提供答案不等于答案已经权威核实；模型也不能自行把答案标记为“已核实”。当前版本没有新增人工审核通过的管理接口，pending 不是完整的审核工作流。

### 2.3 句子拆分和字符位置

- 空行分段；PDF 中的单个换行视为软换行，合并为段内空格。
- 句子保存真实的“第几段、第几句”，句号缩写如 U.S.、Dr. 等做保守保护。
- 保存 char_start、char_end，使用 Python 字符下标的左闭右开区间。
- 下标对应的是数据库中规范化后的文章，不是原始 PDF 的字节位置、页码或页面坐标。
- 如果提取文本没有空行，就保存为一段并提示，不凭空构造原卷段落。
- 前端阅读区同步使用实际段落，不再为了展示把单段正文平均切成若干假段落。

句子拆分仍是规则实现，不能保证处理所有英文缩写、引号和复杂排版。

### 2.4 原文定位必须有可核验的引文

取消关键词选句、最长句兜底。仅在引文能唯一匹配正文且落在一个句子内时绑定句子。

| 定位状态 | 含义 |
| --- | --- |
| exact_quote | 引文唯一出现，且完整落在一个句子内 |
| pending | 引文缺失、太短或无法匹配，等待人工定位 |
| ambiguous | 引文有多处匹配 |
| multi_sentence | 引文跨越多句，不强行指定其中一句 |
| unverified | 旧数据尚未按新规则核验 |

唯一匹配只证明引文存在于文章中，不证明它一定能支持答案。题目仍保留待复核状态。主旨题可能依赖整篇文章，暂时不强行绑定单句。

### 2.5 失败回滚和重复提交

- 模型提取和分析放在数据库写事务之前，减少等待模型期间占用写锁。
- 文章、句子、题目在同一个事务中保存；中途失败则全部回滚。
- 自动导入同一年度、考试类型、Text 的已有 auto_/custom_ 记录时，返回 409，要求先核对题库，不自动覆盖。
- 手动录入同一文章、同一题干时也会拦截重复提交。
- 在写锁内再次检查重复，降低并发重复请求的风险。
- 自动导入重复判定不覆盖所有历史自定义 ID 规则，也不提供合并或版本管理功能。

## 4. 给各模块组员的对接说明

### 后端 API

主要接口仍为：

- POST /api/exams/auto-import
- POST /api/exams/import
- GET /api/questions/full

自动导入增加可选参数 answer_source_note，作为来源备注。自动导入结果增加 warnings，提醒未复核、段落不明确或定位待确认等情况。

题目完整响应新增 answerSource、answerSourceNote、reviewStatus、sourceQuote、locationStatus、sourceSentenceId。只有 exact_quote 才把定位作为确认的单句引用返回。

校验失败示意：

```json
{
  "detail": {
    "code": "invalid_exam",
    "message": "真题校验失败，未入库",
    "issues": ["第 22 题必须有完整且非空的 A/B/C/D 四个选项"]
  }
}
```

重复导入使用 HTTP 409 和 code=duplicate_exam；结构校验失败使用 HTTP 422。前端已处理这些结构化错误。

### 数据库与演示快照

- 在原有表上增加字段，没有重建整套数据库。
- init_db 在种子数据初始化之前执行增量迁移，可重复运行。
- 旧答案、旧句子关联不自动改写；旧记录来源默认为 unknown、待复核、定位 unverified。
- 旧句子没有可核验的字符范围时保持 NULL，不虚构下标。
- 导入旧快照支持字段缺失的默认值；新快照保留来源和字符范围。
- 正式合并并启动前，应由数据库负责人备份现有 app.db；不要把“迁移兼容”理解成无需备份。
- 不要为本次升级直接运行 load_demo.py --reset；这个参数原本就会删除既有 auto_ 演示导入记录。

### Agent 与前端

- Agent 提取必须输出原卷题号；缺数据应明确失败，不允许自动补成看似完整的五题。
- source_quote 应逐字摘录，不能写解释性转述冒充原文。
- 没有可靠定位时展示“待人工定位”，不要给出随机句子。
- 旧数据出现“来源待确认”是保守兼容策略，不代表原来的答案已被改错。

### 测试组

建议人工验收：同一篇试卷正常导入五题；重复提交被拦截；删去中间一道题或一个选项后整篇拒绝；模型推断答案刷新后仍显示待复核；无引文不出现伪定位。

还需要准备可授权使用的真实文字版 PDF 和扫描版 PDF，分别检查正文是否完整、段落是否正确、题号与答案是否和原卷一致。
