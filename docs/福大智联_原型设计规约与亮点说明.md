## 0 使用说明

### 0.1 本文档怎么用

1. 第 1 章用于在墨刀/Axure 中搭建**全局母版**：侧栏、页头、配色、字体、卡片、提示。

# 1 全局 UI 视觉规范与布局框架

## 1.1 设计语言

系统的视觉基调是"学术工作台"而不是"聊天玩具"：浅灰画布、白色卡片、深灰蓝主色、低饱和语义色、衬线字体承载英文原文。所有页面共享同一套 `Layout`、`PageHero`、`SectionHeader`、`StatCard`、`Tag`、`ToolTrace`、`Toast`、`EmptyState`、`ProgressBar`、`FeatureCard` 组件。

| 设计原则 | 在界面上的体现 |
| --- | --- |
| 内容优先 | 无大面积渐变与插画，卡片以边框和轻阴影区分层级 |
| 证据可视 | 工具链、真题出处、答案来源都有独立标签或卡片 |
| 状态可辨 | 正确/错误/薄弱/到期/待审核均有固定语义色 |
| 无剧透 | 阅读训练提交前不显示答案与陷阱标签 |
| 可降级 | 后端不可用时显示"本地模式"，不白屏、不放假答案 |

### 1.2.2 语义状态色（来自 `Tag.tsx` 的 `toneStyles`）

| 语义 | Tone | 主色 | 浅底 | 深文字 | 使用场景 |
| --- | --- | --- | --- | --- | --- |
| 长难句/信息 | `blue` | `#3B82F6` | `#EFF6FF` | `#1D4ED8` | 长难句卡、定位句高亮、文章标签 |
| 正确/已连接 | `emerald` | `#10B981` | `#ECFDF5` | `#047857` | 正确、答案、FastAPI 已连接、大纲词 |
| 知识/词库 | `cyan` | `#06B6D4` | `#ECFEFF` | `#0E7490` | 大纲词核验卡、词库指标 |
| 复习/到期/提示 | `amber` | `#F59E0B` | `#FFFBEB` | `#B45309` | 到期词、掌握度、熟词僻义、长难句标记 |
| AI/练习/题型 | `violet` | `#8B5CF6` | `#F5F3FF` | `#6D28D9` | Agent、题型、DeepSeek 生成、推理陷阱 |
| 错误/对照 | `red` | `#EF4444` | `#FEF2F2` | `#B91C1C` | 错误、薄弱、偷换概念 |
| 中性 | `slate` | `#94A3B8` | `#F1F5F9` | `#475569` | 难度、建议时间、非大纲 |

**使用规则**：

1. 同一语义在 8 个页面保持同一颜色，不得在某个页面把"正确"画成蓝色。
2. 陷阱标签颜色由 `TRAP_TYPES[].tone` 决定：偷换概念红、扩大/缩小范围黄、正反混淆红、无中生有青、过于绝对红、过度推理紫、张冠李戴紫。
3. 主按钮统一深灰 `slate-800`，不使用品牌蓝填充，避免与"链接/信息"混淆。
4. 金色只用于"到期/复习/提示"，绿色只用于"正确/已连接/已完成"。

## 1.6 全局交互与状态规则

| 规则 | 说明 |
| --- | --- |
| 加载态 | 指标卡用 `animate-pulse` 骨架；列表用旋转图标 + "正在读取…"；对话用三点 `typing-dot` 动画 |
| 错误态 | 页面内联提示（红色或黄色）+ 重试入口；不使用弹窗打断 |
| 空态 | 统一 `EmptyState`，必须给出下一步动作 |
| 成功反馈 | Toast，2.8 秒自动消失，不阻塞 |
| 禁用态 | 按钮 `disabled` 降低透明度并禁止点击；提交后按钮文案变"已提交" |
| 键盘 | Enter 发送、Shift+Enter 换行；单词行支持 Enter/Space 进入复习；输入框有焦点描边 |
| 动画 | 卡片悬浮 `translateY(-2px)` + `shadow-md`；Toast 180ms 淡入上移；进度条 300ms |
| 滚动 | 侧栏与主区独立；阅读页左文右题独立滚动；长回答区域内部滚动，不撑破页面 |
| 数据口径文案 | 词频处必须写"当前题库内出现次数"，不得写"历年考频"；答案来源必须显示"待复核/用户提供/AI 推断" |

### 2.1.3 文本描述与业务校验规则

| 位置 | 文案/规则 |
| --- | --- |
| 真题篇章卡 | 数值取 `/api/meta` 的 `passage_count`；辅助文案 `{question_count} 道题目 · {sentence_count} 个句子 · 点击浏览` |
| 大纲词汇卡 | 数值取 `vocab_count`，使用中文千分位；辅助文案"SQLite 考研词库 · 去重后 · 点击浏览" |
| 单词本卡 | 数值取本地 `words.length`；辅助文案"平均掌握度 N% · 点击复习" |
| 已练习卡 | 数值取 `records.length`；已连接时文案"practice_records 实时同步 · 点击看报告"，否则"答题记录自动沉淀" |
| 指标加载 | 未返回且未失败时显示骨架；失败时显示"—"，辅助文案改为"后端未连接 · 启动 FastAPI 后自动恢复" |
| 功能卡元信息 | 句子卡"5 步 · 2 个工具"；选项卡"{题数} 题 · {陷阱数} 类陷阱"；对话卡"DeepSeek · 4 个工具"；单词本卡"{词数} 个词 · {到期数} 待复习" |
| 到期横幅 | 必须使用"今天有 N 个单词到期"，N 为 `nextReview <= now` 的数量 |

| AD-05 | 编辑题干/选项/答案 | 实时重算校验清单 | 正确答案变化时，原"正确"标签自动移除并提示复核 |
| AD-06 | 点击"保存草稿" | 写入 `draft`，`revision=1` | Toast"已保存草稿，学生端不可见" |
| AD-07 | 点击"生成解析" | 调用批量分析 | 生成中禁用操作；完成后仍为 `pending`，不自动审核 |
| AD-08 | 点击"提交审核" | 校验 `readiness` | 不通过：弹窗列出 issues；通过：状态变 `reviewed` |
| AD-09 | 点击"发布" | 要求已审核且审核人非空 | 状态变 `published`，学生端立即可见 |
| AD-10 | 点击"撤回" | 状态回 `draft`，清空审核字段 | 学生端立即不可见；缓存失效 |
| AD-11 | 重复导入同 Text | 拦截并提示 | "该 Text 已存在；更正须使用更正流程并填写 expected_revision" |
| AD-12 | 并发编辑 | 提交时携带 `expected_revision` | 版本冲突提示"当前 revision=N，请重新查看" |

**页面状态机**：

```text
未上传 → 已解析(parsed) → 草稿(draft) → 已审核(reviewed) → 已发布(published)
                                   ↑                              │
                                   └──────── 撤回(withdraw) ──────┘
```

## 4.2 ToolTrace 工具调用可视化

### 4.2.1 当前实现（✅）

| 位置 | 形态 | 说明 |
| --- | --- | --- |
| `SentencePage` | `ToolTrace` 卡片 | 标题"本次执行记录"；右上"N 次调用"；每条显示扳手图标、工具名（等宽字体）、中文摘要、耗时 ms |
| `OptionsPage` | `ToolTrace` 卡片 | 标题"本次诊断工具链"，位于解析态底部 |
| `ChatPage` | 紧凑工具条 | 标题英文"Tool trace"；每个工具是一个小胶囊：`工具名 · 摘要`，摘要超过 180px 截断，悬停显示全文 |
| 空数据 | 不渲染 | `tools.length === 0` 返回 `null` |

**轨迹数据来自后端**，不是前端拼装；模型无法修改 `tool` 与 `summary`。这是可信度的核心。

### 4.2.2 原型增强建议（○ 折叠面板）

当前 `ToolTrace` 是平铺卡片，没有展开/收起。若作业要求"折叠面板"，按以下规约绘制，但备注必须写"当前为平铺展示，折叠为原型增强"。

| 状态 | 表现 |
| --- | --- |
| 收起（默认） | 一行：工作流图标 + "Agent 工具链" + "N 次调用"绿色标签 + 总耗时 + 展开箭头 |
| 展开 | 逐条工具卡：序号、工具名、摘要、`args` 键值对、耗时、状态圆点 |
| 单条展开 | 点击工具行展开参数 JSON；再点收起 |
| 失败条 | 红色左边条 + "失败"标签 + 错误类型；成功为绿色 |
| 键盘 | Enter/Space 切换展开；`aria-expanded` 同步 |
| 动画 | 高度过渡 200ms；箭头旋转 180° |

**展开后的字段**：`tool`、`args`（如 `word_count`、`grammar`、`limit`）、`summary`、`duration_ms`。不得展示 API Key、完整原文、用户隐私。

### 4.2.3 答辩话术

> 这条工具链不是模型"说它调用了"，而是后端真实执行后返回的记录。前端只负责展示，因此不可能出现"模型编造工具调用"的情况。

### 4.3.2 交互规则

1. 点击即发送，不填充输入框，减少一次操作。
2. 发送中（`typing`）全部禁用，防止重复请求。
3. 胶囊不随对话消失，始终在输入区上方，方便连续追问。
4. 胶囊文案是固定领域任务，不随上下文动态变化；上下文由顶部下拉控制。
5. 胶囊内容与后端意图路由的关键词对齐，保证点击后能命中对应工作流。

### 4.3.3 与意图路由的对应

| 快捷指令 | 命中意图 | 后端处理 | 是否走模型 |
| --- | --- | --- | --- |
| 解析这个句子的从句 | 长难句 | 句子工作流 + 五步拆解缓存 | 否 |
| 提炼本段核心词 | 核心词 | 当前篇章词库筛选 | 否 |
| 分析这道题的错误选项 | 选项 | 选项工作流 + 错题记录 | 否 |
| 安排本周复习计划 | 复习计划 | `get_report` + 到期词 | 是（开放讲解） |
| 总结段落主旨 | 段落主旨 | 原文首尾与题干定位抽取 | 否 |
| 查一个熟词僻义 | 熟词僻义 | 词库检索 + 陷阱知识 | 是（开放讲解） |

## 4.4 一键沉淀闭环

### 4.4.1 三条沉淀路径（✅ 已实现）

| 路径 | 触发 | 写入 | 用户可见结果 |
| --- | --- | --- | --- |
| 长难句加词 | 句子页词卡"单词本" | `user_vocab_book` | 单词本出现该词，带原句语境与出处 |
| 对话归档 | "把 X 加入单词本" | `user_vocab_book` | 对话提示已归档；前端 `refresh()` |
| 资料库加词 | 词库行"加入单词本" | `user_vocab_book` | 按钮变"已在单词本" |
| 错题沉淀 | 提交答案 | `practice_records` | 报告正确率、薄弱题型、最近练习更新 |

### 4.4.2 交互规约

| 环节 | 规约 |
| --- | --- |
| 加词前 | 校验单词非空、去重（不区分大小写） |
| 加词中 | 乐观更新，按钮立即反馈；失败保留本地并提示 |
| 加词后 | Toast 明确"首次复习安排在明天"；首页单词本 +1；单词本页可见 |
| 语境 | 必须携带原句 `context` 与出处 `source`，不得只存单词 |
| 释义 | 优先词库释义；有僻义时拼接"基础释义；熟词僻义：…" |
| 错题 | 提交即写入，无需额外按钮；解析态显示"已记录" |
| 复习 | 单词本"记住/没记住"推进 `next_review`，首页到期横幅与报告建议同步 |
| 边界 | 当前**没有独立错题本页面**，错题只进入 `practice_records` 与报告；原型若画"错题本"必须标 ○ |

# 5 原型设计重要突出特点总结（博客可直接使用）

## 亮点一：把"工具链"做成可信度凭证，而不是装饰

多数 AI 产品只展示一段回答；本系统把 `check_syllabus_vocab`、`search_past_exams`、`add_to_vocab_book`、`record_trap_mistake` 的**真实执行记录**（工具名、参数摘要、耗时）直接展示在回答下方。工具链由后端生成，模型无权改写，因此用户看到的"它查了什么"与实际执行完全一致。

**博客配图建议**：`ChatPage` 一次长难句回答，圈出工具条与"工具直答"标签。

## 亮点二：证据敏感路径锁定，回答可以被逐句核对

长难句、选项分析、单词归档三类任务不走模型改写，直接返回工具结果；引用由后端过滤为同篇句子并强制当前句置顶。界面上每个引用都有出处标签，每道题的正确答案与选项陷阱都带"答案来源"和"待人工复核"提示。这套设计直接回应了"AI 解析到底能不能信"的答辩追问。

**博客配图建议**：`SentencePage` 的"真题溯源"卡 + `OptionsPage` 的"答案来源"标签。

## 亮点三：作答态与解析态两阶段，拒绝"先看答案再解释"

阅读训练提交前只显示干净的四选项，不显示正确答案、陷阱标签、反证与解题路径；提交后才进入解析态，逐项给出 4px 陷阱色条、原文反证、定位句高亮与工具链。这个状态机把"练习"与"复盘"分开，是原型里最容易被评审感知的交互差异。

**博客配图建议**：同一道题的两张截图，左"作答态"、右"解析态"。

## 亮点四：一次操作改变下一次页面看到的数据

加词写入 `user_vocab_book`，答题写入 `practice_records`，复习推进 `next_review`。首页指标、单词本列表、到期横幅、报告正确率与薄弱题型会随之变化。原型中应把这四个页面串成一条可见的闭环，而不是四个孤立页面。

**博客配图建议**：四宫格：句子页加词 → 首页单词本 +1 → 单词本复习 → 报告更新。

## 亮点五：快捷指令把"会提问"的门槛降到一次点击

对话页提供 4 张起步卡片与 6 个常驻胶囊，覆盖从句、核心词、错项、复习计划、主旨、熟词僻义六类高频任务。每个胶囊都对应后端一个明确的意图分支，点击即发送，不需要用户学习提示词。它既是交互优化，也是"领域 Agent 应该懂什么"的产品表达。

**博客配图建议**：`ChatPage` 起始页 4 卡片 + 对话中 6 胶囊的拼图。

## 可选亮点六：可降级、可交付的演示体验

后端不可用时显示"本地模式"而不是白屏；模型未配置时给出工具兜底而不是假解析；题库通过快照一键恢复。原型中应画出加载态、空态、错误态三套页面，体现"这是一个能演示、能交付的系统"。
