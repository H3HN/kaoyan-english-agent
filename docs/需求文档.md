## 1. 项目概述

### 1.1 产品定位

面向考研英语一 / 英语二考生的阅读训练工作台，把「长难句拆解 → 真题选项分析 → 生词沉淀 → 间隔复习 → 学习报告」组织为一条可重复执行的学习工作流。

### 1.2 产品目标

1. 让长难句拆解有固定方法，而不是只给一句翻译。
2. 让每道真题的四个选项都能说明「对在哪里、错在哪类陷阱」。
3. 让阅读中遇到的生词自动进入单词本，并按间隔重复安排复习。
4. 用练习记录生成题型正确率与薄弱环节，指导下一步训练。
5. 工具检索与学习状态写入是确定性的，模型只负责开放讲解，避免事实被改写。

### 1.3 当前系统形态

| 部分 | 技术栈 | 作用 |
| --- | --- | --- |
| `web/` | React 19 + Vite + Tailwind CSS v4 | 主前端工作台，8 个页面 |
| `server/` | FastAPI + SQLite | 领域数据、四个工具、三类工作流、学习状态持久化 |
| `kaoyan_agent/` | Streamlit | 早期 MVP，保留但不作为当前主入口 |

前端通过 `/api` 代理访问后端，开发环境后端端口 `8000`，前端端口 `5173`。

## 2. 核心问题

> 以下结论由第 3 节问卷数据归纳，属于**基于现有样本的产品判断**，待产品负责人确认。

### 2.1 问题陈述

备考阅读的主要矛盾不是「缺题、缺课、缺背词工具」，而是**做题之后的复盘没有形成闭环**：

1. **长难句读不懂是第一痛点**：阅读困难排序题（Q9）中，「长难句读不懂（每个词都认识，连起来不理解）」综合得分 4.07，56.25% 的受访者将其排在第 1 位；「词汇量不够、生词太多」得分 3.88，46.67% 排第 1 位。
2. **做题量在积累，错因却没有被解释清楚**：51.22% 的人「二选一」时经常选错；但仍有 17.07% 基本不分析错题，14.63% 只看答案不深究。选项错因中「偷换概念」被 63.41% 选中，说明用户知道自己会掉进陷阱，却缺少逐项归因的方法。
3. **生词与复习没有沉淀**：48.78% 遇到生词只靠上下文猜，只有 24.39% 会查词典并记录；仅 9.76% 按艾宾浩斯曲线复习，29.27% 背了就忘，34.15% 凭感觉复习。
4. **缺少计划与监督**：51.22% 认为备考中最缺的是「学习计划与监督」，高于「优质学习资料」的 24.39%。

因此，本产品要解决的核心矛盾是：**碎片化的做题与背词工具很多，但结构理解、错项归因、生词复习三件事没有被同一条工作流串起来，用户也无法判断 AI 给出的解析是否可信。**

### 2.2 现有方案与不足

| 现有方式 | 使用率（n=41） | 主要不足 |
| --- | --- | --- |
| 背单词 APP（墨墨 / 百词斩 / 不背单词） | 78.05% | 只解决词汇量，脱离真题语境，不解释句子结构 |
| 自学刷真题 | 56.10% | 对答案为主，缺少逐项陷阱归因与生词沉淀 |
| 看网课 | 41.46% | 被动输入，无法针对个人错题即时反馈 |
| AI 工具辅助（ChatGPT / 文心一言等） | 17.07% | 输出不稳定、缺少真题出处，31.71% 的用户要求解析必须 100% 准确 |
| 报辅导班 | 4.88% | 成本高，节奏固定 |

本产品的差异化：

- **结构优先**：五步拆解给出主干、从句、修饰、逐层翻译与语法点，而不是一句译文。
- **逐项归因**：每道题的 A–D 都标注陷阱类型，并定位来源句。
- **语境沉淀**：拆句与做题时直接加入单词本，保留原句语境，按间隔重复复习。
- **可核查**：工具调用与真题引用由后端返回，模型只负责开放讲解，降低「一本正经胡说」的风险。

### 2.3 产品非目标

- 不做整卷模考与写作、翻译、完形等非阅读题型。
- 不做社交、排行榜、课程售卖。
- 不做公网多用户 SaaS（当前无登录与权限系统）。
- 本期不做原生手机 APP 与微信小程序；先以 Web 响应式界面覆盖，移动端需求列入后续迭代（调研中 34.15% 首选手机 APP，43.90% 表示「都可以」）。

### 3.4 数据局限

1. **非概率便利样本**：56 份，83.93% 为理学/工学，50% 为大三，不能代表全国考研人群。
2. **有效样本较小**：考试相关题项 n=41，比例误差较大（50% 附近的比例，95% 置信区间约 ±15 个百分点），不宜过度解读小数点差异。
3. **多选题占比之和大于 100%**，排序题使用平台加权综合得分，不可与单选题比例直接比较。
4. **自报偏差**：63.41% 声称会仔细分析错题，但二选一选错率仍达 51.22%，实际复盘质量可能低于自报。
5. **未覆盖**：付费意愿、留存、竞品具体使用时长、英语一/英语二分层差异（子样本过小）。

## 6. 功能需求

优先级定义：**P0** 为当前学习闭环必需，**P1** 为增强体验，**P2** 为辅助或演示性质。

### 6.1 全局框架与导航（FR-00，P0）

- 采用左侧固定导航 + 右侧内容区布局，窄屏折叠为抽屉。
- 导航共 8 项：首页、长难句拆解、阅读真题训练、AI 对话、我的单词本、资料库、学习报告、领域知识库。
- 未知路由重定向到首页。
- 页面标题随路由切换。
- 全局 Toast 提示成功 / 错误 / 信息。
- 顶部或页面内展示后端连接状态（已连接 / 本地模式）。
- 所有 `/api` 请求经统一客户端 `web/src/lib/api.ts` 发出，开发环境由 Vite 代理到 `127.0.0.1:8000`。

### 6.2 首页仪表盘（FR-01，P0）

## 7. 数据需求

### 7.1 数据表

`syllabus_vocabulary`、`exam_passages`、`exam_sentences`、`exam_questions`、`trap_rules`、`user_vocab_book`、`practice_records`、`agent_runs`、`sentence_breakdowns`。

### 7.2 数据规则

- 数据库文件：`server/data/app.db`，首次启动或 `setup_team.py` 时创建。
- 篇章与题目有发布状态，学生端只读取已发布内容。
- 真题频次统计的是**当前已导入句子切片范围内**的出现次数，不是 2010—2026 全量统计。
- 快照只含 `auto_` / `bank_` / `custom_` 内容，不含个人记录、密钥、原始 PDF、审核审计历史。
- 前端本地缓存键为 `kaoyan-studio-v1`，仅作离线兜底。

### 7.3 数据来源

- 词库：KyleBing/english-vocabulary（BSD-3-Clause），去重后 5,064 条。
- 真题与解析：公开 PDF 导入 + 2 篇内置示例；原始 PDF 不随仓库分发。
- 演示数据：`seed.py` 生成 7 个单词与 20 条练习记录，不代表真实个人历史。

## 9. 当前版本边界与已知限制

1. **无账号与多用户隔离**：所有学习记录属于本机同一用户，不能直接部署为公网多用户服务。
2. **学生端不提供题库导入**：旧 HTTP 导入接口 `POST /api/exams/import`、`POST /api/exams/auto-import` 固定返回 410；前端仍保留 `ExamImportForm` 组件，但当前没有任何页面挂载它。
3. **导入与建库只走命令行**：题库维护需要使用 `server/scripts/` 下的脚本。
4. **拆解缓存有限**：仅 6 份已有拆解可直接复用，其余句子需要配置模型 Key 才会生成。
5. **未配置 Key 时能力降级**：新句子拆解、开放讲解类问答不可用或回退确定性答案。
6. **频次口径**：词频是当前导入句子范围内的相对频次，不能等同于历年全量考频。
7. **报告由前端计算**：`/api/report` 已存在，但当前学习报告页面读取的是同步后的前端状态。
8. **文档与代码存在差异**：README 仍提到 `/comparison` 页面与 153 个句子切片，当前路由中无 `/comparison`，实际句子数为 1,295。
9. **无学习计划、提醒与监督**：首页只有静态「今日学习任务」和到期单词提示，没有周计划、通知提醒、连续打卡；而调研中 51.22% 的用户认为最缺的正是「学习计划与监督」。
10. **仅 Web 端**：没有原生手机 APP 与微信小程序；调研中 34.15% 首选手机 APP，43.90% 表示形态都可以。

## 11. 待确认事项

1. 第 2 节「核心问题」是由第 3 节问卷数据归纳的产品判断，需产品负责人确认措辞与边界。
2. 词频统计口径：README 写 153 个句子切片，当前数据库实际 1,295 句，需统一对外口径。
3. 是否恢复「定制效果对比」页面：`COMPARISONS` 数据仍在 `content.ts`，但路由已移除。
4. 学生端真题导入是否恢复：63.41% 的受访者期待「导入真题并逐句拆解」，但当前接口返回 410、组件未挂载；需决定重新开放，还是维持团队代传。
5. 是否纳入学习计划与监督：这是调研中排名第一的缺口（51.22%），当前无对应功能；需决定本期实现周计划/提醒，还是明确列为非目标。
6. 移动端优先级：34.15% 首选手机 APP、43.90% 表示都可以；当前仅 Web 响应式，需确认是否排期原生 APP 或小程序。
7. 是否需要多用户与登录：若需要，需补充用户表、鉴权与数据隔离需求。
8. 解析准确性验收：90.25% 的受访者要求至少 90% 准确，需定义抽检样本量、错误率阈值与缓存拆解的复核机制。
9. 学习报告的统计来源：继续前端计算，还是改用 `/api/report` 聚合。
