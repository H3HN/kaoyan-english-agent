## 1. `/api/questions/full` 性能重构（P0）

### 问题

原实现 `app.py` 逐题调用 `_full_question()`：每题 3 次独立 SQL（题目 + 定位句 + passage 文本），340 题 = **1021+ 次查询**（典型 N+1）；且每题内嵌整篇 passage 全文，一篇 5 题重复传 5 遍，响应体 **1.8MB**。

### 方案

新增 `_assemble_full_question()` 纯组装函数，路由改为**固定 3 个查询**（题目批量 → 涉及句子 IN 批量 → 涉及 passage IN 批量），并增加可选筛选参数：

| 参数 | 作用 |
| --- | --- |
| `year` / `exam_type` / `text_number` | 按阅读训练级联筛选（2000–2100 / 英语一、英语二 / 1–4，越界 422） |
| `include_passage` | 默认 `true`（旧行为）；`false` 时每题 `passage` 为空字符串 |

**字段契约与旧版逐字段一致**（含 `location`/`sourceSentence`/`sourceSentenceId` 仅在 `exact_quote` 时返回的规则），`include_passage=true` 默认行为完全兼容旧前端。

### 前端配套（`web/src`）

阅读训练页改为两段式加载：初次 `include_passage=false` 拉全量目录（分组/筛选用元数据），选中某篇时按筛选参数拉该篇 5 题（带原文），`fetchedPassageKeys` 保证每组最多拉一次；失败可重试（从缓存集合移除），左栏有「正在加载原文…」过渡提示。

### 实测（真实 340 题库）

| 场景 | 耗时 | 响应体积 |
| --- | --- | --- |
| 默认全量（兼容模式） | 59ms | 1807KB |
| `include_passage=false`（初次加载） | 34ms（**1.7x**） | 950KB（**-47.4%**） |
| 筛选单篇（选中组加载） | 5ms | 28KB |

## 2. chat 工作流补 `agent_runs` 日志（P1）

### 问题

`run_chat_workflow` 是三条工作流中唯一不写 `agent_runs` 的（约 410 行 chat 逻辑零审计）；且 chat 内部转发调用 sentence/options 工作流时会各自写一条日志，审计时无法区分「用户直接请求」与「chat 内部转发」，错误归因。

### 方案

- `_log_run()` 增加 `source` 参数（`direct` / `chat`），写入 `input_json` 顶层字段；旧日志无该字段，读取方按缺省处理。
- `run_sentence_workflow` / `run_options_workflow` 增加 `log_source="direct"` 关键字参数；chat 的两个转发点（长难句分支、选项陷阱分支）传 `log_source="chat"`。
- `run_chat_workflow` 拆出 `_chat_pipeline()`（原 LLM polish 逻辑），外层统一写 `workflow="chat"` 日志：input 存消息前 200 字符与 context_id，output 只存摘要（llm_used / section 数 / 工具名列表 / 引用数），不存全文。

### 实测

`POST /api/workflow/chat`（"解析这个句子的从句"）后 `agent_runs` 新增两行：`workflow=chat, source=direct` 与 `workflow=sentence, source=chat`，归因正确。

## 3. 410 死代码清理（P1）

### 删除（app.py 761 → 537 行，净删约 224 行）

| 项 | 原因 |
| --- | --- |
| `auto_import_exam` / `import_exam` 函数体（约 150 行） | 路由 410 后永不执行；校验/事务/回滚逻辑已由 `question_bank.py` 的 `_save` 承接并有测试 |
| `_download_pdf_text` | **潜伏 SSRF**（无内网地址防护、重定向跟随、先下载后限大小）；死代码直接删除优于修复 |
| `_insert_sentences` / `_insert_question` / `_analysis_fields` / `_manual_duplicate` / `_auto_duplicate` / `_duplicate_error` / `_validation_error` | 仅被上述死函数调用 |
| `AutoImportRequest` / `ExamImportRequest` 模型 | 无消费者 |
| `agent_runs` 路由函数体 | `Depends(_team_cli_only)` 先抛 410，函数体从未执行 |
| 头部 imports：`io` / `uuid` / `httpx` / `PdfReader` / `datetime` 及 8 个 exam_import、llm 导入 | 不再使用 |

### 保留的 410 契约

`POST /api/exams/import`、`POST /api/exams/auto-import`、`GET /api/agent/runs` 三个路由**保留并继续返回 410**（`test_student_routes_reject_draft_ids_and_http_management` 覆盖），旧客户端与文档链接仍收到明确的迁移提示。

### `_slice_text` 迁移

从 `app.py` 迁至 `exam_import.py` 更名 `slice_text()`（纯文本切分，归属确定性模块）；`scripts/question_bank.py` 的 `prepare-pdf` 改从 `exam_import` 导入，**消除了团队 CLI 对 Web app 模块的依赖**。行为不变，含新增单测。
