# 答辩演示与追问准备

## 1. 五分钟演示路线

1. **首页（30s）**：5,064 条考研词条、8 篇导入真题 + 2 篇内置示例、8 条陷阱规则、FastAPI 已连接。强调页面不是静态稿，数据来自 SQLite。
2. **长难句（90s）**：默认最长句 → 五步拆解 → 向下滚动看 `check_syllabus_vocab` / `search_past_exams` 的调用记录 → “大纲词核验”里的等级与切片频次 → “真题溯源”里的出处 → 点一个“单词本”按钮。
3. **选项分析（60s）**：选 C 提交 → 显示“缩小范围” → 下方出现 `record_trap_mistake` 工具链与出处 → 说明已写入 `practice_records`。
4. **AI 对话（60s）**：点“解析这个句子的从句” → 回答底部出现 Tool Trace 与真题出处 → 点“查一个熟词僻义” → address / plant / subject 的不同义项。
5. **真题导入（30s）**：阅读真题训练页 → 添加真题 → PDF 自动导入；粘贴公开 PDF 地址，DeepSeek 抽取文章/题目/选项，答案序列可选；导入后题目立即出现在题库。
6. **动态选材（20s）**：长难句页和 AI 对话页的文章下拉都来自 `/api/passages`，可切换 8 篇导入文章；长难句按句生成五步拆解并缓存。
7. **单词本 / 报告（40s）**：刚才归档的词已在单词本，复习按钮会更新 SQLite；报告页读取练习记录。
8. **架构页（20s）**：打开 `http://localhost:8000/docs`，展示 OpenAPI；说明前后端通过 `/api` 解耦。

## 3. 可能被追问的问题

### “你们说 5500 词，实际多少？”

当前公共词库去重后 5,064 条，另补充了内置真题中的缺失词。**不要宣称是官方 5,500 完整大纲**。正确说法：

> 表结构和导入流程按 5,500 词规模设计；当前去重后 5,064 条，覆盖内置真题与核心熟词僻义，后续直接替换词库文件即可扩容。

### “考频是怎么来的？”

当前 `exam_frequency` 是**已导入 8 个句子切片内的出现次数**，不是 2010–2026 全量统计。正确说法：

> 频次字段已经落地，但当前语料只有两篇真题切片，所以只用于演示排序；导入全量真题后重新跑统计脚本即可得到真实考频。

### “大模型在哪里？是不是模型自己编的？”

当前不是裸 LLM，而是**工具层 + 受控生成层**：

> 大纲属性、真题出处、错题归档由 SQLite 工具先确定；长难句、选项分析与归档直接返回确定性结果，不经过模型。只有熟词僻义、复习计划等开放讲解才交给 DeepSeek。回答里的 `tool_trace` 和 `citations` 由后端直接返回。

可以现场补充：

> 前端回答底部会标记“DeepSeek 生成”；如果断网或额度异常，工具链仍然可见。测试中曾出现 2023 上下文混入 2024 句子，因此把证据敏感路径锁成确定性，模型只做开放讲解。

### “和直接问 ChatGPT 有什么区别？”

三个可验证差异：

1. **事实边界**：词条是否在大纲、等级、熟词僻义来自 SQLite，不是模型记忆。
2. **可追溯**：每个例句带 `[出处：2024 英语一 Text 1 第1段第4句]`。
3. **状态联动**：单词会进入单词本并带语境；错题会写入 `practice_records`，报告页立刻能读到。

### “工作量是不是都花在前端？”

前端有 8 个页面和统一设计系统；后端有 8 张表、4 个工具、3 类工作流、20+ API 路由、OpenAPI 文档、种子数据导入。前后端通过 `/api` 解耦，不是把 Streamlit 换皮。

### “数据从哪来，有没有版权问题？”

- 词库：KyleBing/english-vocabulary，BSD-3-Clause，仓库保留 LICENSE。
- 真题：项目内置示例文本；只用于课程演示。
- 频次：明确标注为切片频次，不冒充官方统计。

## 4. 不要说的话

- 不要说“覆盖 2010–2026 全量真题”。
- 不要说“5500 词全部收录”。
- 不要说“考频来自官方数据”。
- 不要说“模型自己查了数据库”；事实来自工具层，模型只负责生成讲解。
- 不要把“页面能点”当成“系统完整”，要主动展示数据库与 API。
