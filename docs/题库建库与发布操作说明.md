## 最新调整：完整题目先供学生练习

根据实际使用要求，完整原文、五题四选一、提供的答案及来源齐全时，可先开放基础练习，解析和定位不再阻塞学生阅读与答题。

```bash
python scripts/question_bank.py publish-practice <passage_id> --revision <当前版本> --actor "操作人"
```

此动作仍校验整篇结构和答案来源，并记录审计及版本；文章设为published，题目标记practice，不填写虚假的人工解析审核记录。学生能阅读、选择答案、查看对错并保存作答；缺解析显示“待完善”，不生成编造的陷阱分析。完整解析复核仍走原review→publish流程；修订已发布内容须先withdraw或按原update流程处理。旧草稿及不完整seed不会自动开放。

本次合并已包含完整共享快照：68篇、340题、1295句及6份已有拆句缓存，题目含答案和A—D解析。个人学习记录、密钥、原始PDF不共享。队友首次安装请在server目录运行 `python scripts/setup_team.py`，恢复题库并明确开放基础练习；已有数据库时该命令拒绝覆盖。详见[队友复现指南](队友复现指南.md)。其余2篇3题为seed演示，不计入340题。下文原完整解析审核流程适用于发布完整教学解析；其中“缺解析不能发布”仅约束原publish动作，不适用于新增publish-practice。快照恢复仍重置草稿，恢复后需按需要重新开放。

## 一、现在的使用方式

学生打开系统即可学习，学生端没有导入按钮。团队提前完成：

```text
整理原文与可靠答案 → JSON 格式校验 → 批量导入草稿
→ 补齐解析和证据 → 人工审核 → 发布 → 学生读取
```

管理入口是服务器本地命令行，不是公开 HTTP 接口。需有服务器文件访问权限；`--actor` 是审计署名，不是登录认证。旧 `/api/exams/import`、`/api/exams/auto-import` 返回 410；旧 `scripts/auto_import.py` 给出迁移提示。不要继续使用旧页面导入教程。

## 二、先准备环境与备份

按项目现有依赖说明安装后端依赖；以下命令从 `server` 目录运行，`python` 指向装好项目依赖的虚拟环境。

先停止写入并备份 `server/data/app.db`。新版本会按需为旧库补列，不删旧内容；**旧数据及示例默认都不自动发布**。没有已发布文章时学生页面显示空态，这是预期行为。

如想独立试跑，可在每条管理命令的子命令前加 `--database data/bank-trial.db`。此测试库不会自动成为 API 使用的 `app.db`；API 默认仍使用后者。

## 三、准备 JSON：比反复解析 PDF 更适合批量建库

```bash
python scripts/question_bank.py template --output bank-template.json
python scripts/question_bank.py validate bank-template.json
```

模板含明确标注的合成英文和占位题，**不是可发布真题**，必须替换。输出文件已存在时会报错，避免覆盖组员修改。

顶层 `format` 固定为 `kaoyan-question-bank-v1`，`passages` 每批 1—100 篇，文件上限 10MB。每篇包含：

| 字段 | 填写方式 |
| --- | --- |
| year / exam_type / text_number | 年份整数、英语一或英语二、Text 1—4 |
| source_note | 原文来源、版本、页码或可核查出处；发布前必填 |
| paragraphs | 字符串列表，一项一段，保留真实段落；不要把排版换行当段落 |
| questions | 必须完整五题，保留原卷题号：Text1 为21—25，依次至36—40 |

每题包含 `number`、`question_type`、`content`、完整 `options` A/B/C/D、`correct_answer`（一个大写字母）。另需整理：

| 字段 | 用途 |
| --- | --- |
| answer_source | provided 可靠答案来源提供；manual 人工核对；inferred 模型推断；unknown 未确认。缺省 unknown，不冒充可靠答案 |
| answer_source_note | 答案来源与核对依据；人工署名可写在这里 |
| source_quote | 逐字摘录的原文证据，程序只在唯一单句匹配时绑定位置 |
| evidence_note | 跨句、主旨或全文题的证据说明；不能唯一定位时，发布前必须填写 |
| analysis | 可选；完整 A/B/C/D 对象，各含 trapType 和 explanation，只有正确选项 trapType 为“正确” |
| steps | 可选；非空解题步骤列表 |

允许先不填 `analysis` / `steps` 导入草稿；若提供则须完整有效。校验通过只说明格式正确，不代表答案、语义和解析已经正确。

可选 PDF 转换入口（文字型 PDF，不做 OCR）：

```bash
python scripts/question_bank.py prepare-pdf exam.pdf --year 2025 --exam 英语一 --text-number 1 --answer-key ABCDA --source-note "填写实际来源" --answer-source-note "填写实际答案出处" --output prepared.json
```

这里 `ABCDA` 仅展示格式，并非真题答案。此操作调用已配置的模型，只生成待检查 JSON，不直接入库；扫描件先 OCR。PDF 版式和 Text 分段仍可能识别错误，必须对照原文校对。结构化 JSON 导入本身不调用模型。

## 四、导入与查看

```bash
python scripts/question_bank.py import bank.json --actor 王世豪
python scripts/question_bank.py list --status draft
python scripts/question_bank.py show bank_2025_1_1
```

新 ID 按 `bank_年份_考试类型编号_Text` 生成，英语一编号1、英语二编号2。以 `list` 实际结果为准。每篇独立事务：一篇缺题或写库失败，不会留下半篇文章；同批其他合格文章可以成功，命令返回逐项结果。部分失败退出码也为1，不能把整批当作全部失败后盲目重导。

同年度、考试类型、Text 已存在时拒绝覆盖；请走更正流程。仅对仓库固定的两份未发布、原题号为1/2的残缺演示种子作占位例外：允许另建完整 bank_ 真题，保留种子与旧记录；重启后不会阻断新题更正。除此之外遇到同一 Text 多份旧数据，拒绝猜测替换，需团队先整理冲突。

`show` 给出 `review_issues`，指出缺来源、缺解析、模型推断答案未核对、证据不足等问题。默认草稿 `revision=1`。

## 五、补齐解析、人工审核、发布

已有可靠人工解析可直接放 JSON；也可调用模型预生成选项解析：

```bash
python scripts/question_bank.py analyze bank_2025_1_1 --revision 1 --actor 王世豪
```

模型调用在写事务前完成，五题解析全部格式有效才保存。成功后版本加1，仍是草稿。此命令预生成选项分析和步骤，**不批量预生成每个句子的语法拆解**；句子拆解仍沿用现有学习工作流。需配置 `server/.env` 的 LLM 设置，调用可能产生费用。

审核前逐题检查：原文/段落、题号、选项、可靠答案、四个选项的解释、引文是否真正支持答案。仅“引文出现在原文”不代表推理成立。主旨题等可填写具体的 `evidence_note`，不强行定位第一句。

```bash
python scripts/question_bank.py show bank_2025_1_1
python scripts/question_bank.py review bank_2025_1_1 --revision 2 --actor 审核人 --confirm-checked
python scripts/question_bank.py publish bank_2025_1_1 --revision 3 --actor 发布人
```

上面版本号仅对应“导入一次、生成解析一次”的示例；**每次操作以最新输出 revision 为准**。`review` 需明确确认已人工核对，状态变 reviewed；`publish` 只允许已审核且检查完整的内容，状态变 published。系统记录操作人，但不强制审核人与发布人为不同账号。

学生的篇章/句子/题目列表、搜索、统计、按 ID 查询、选项工作流和聊天上下文均只读取 published。未发布 ID 不能通过直接请求绕过；没有已发布内容时显示空态，不回退填充静态真题。

## 六、发现错误后的更正

可立即撤回，学生端随即不再读取：

```bash
python scripts/question_bank.py withdraw bank_2025_1_1 --revision 4 --actor 王世豪
python scripts/question_bank.py export bank_2025_1_1 --output correction.json
```

也可以直接导出已发布内容并更正，更新本身会撤回为草稿。修改导出的 JSON，保留 `passage_id`、`expected_revision`，不要改变年份/考试类型/Text/题号集合。然后：

```bash
python scripts/question_bank.py validate correction.json
python scripts/question_bank.py import correction.json --update --actor 王世豪
python scripts/question_bank.py show bank_2025_1_1
```

更正保留原题 ID 和既有学习记录，重建句子与偏移并清理旧句子的拆解缓存，再审核发布。旧学习记录保留当时作答结果，**不自动按更正后的答案重判历史记录**。旧题号不能安全映射、版本落后或同 Text 多份数据时会拒绝更正。

```bash
python scripts/question_bank.py history bank_2025_1_1
```

历史记录保存导入、更正前后、解析生成、审核、发布和撤回的快照与操作人。当前没有一键回滚按钮；可参照历史内容重新整理更正 JSON，按最新版本走相同流程。

## 七、数据库、快照与迁移

- `exam_passages` 增加 publication_status、revision、reviewed_by/at、published_at、source_note。
- `exam_questions` 保留先前答案来源/定位字段，增加 evidence_note；`exam_sentences` 保留字符偏移。
- 新增 `bank_events` 审计表，原 schema 9 表增为10表；迁移可重复执行。
- 快照导出支持 auto_ / bank_ / custom_；恢复时无论快照原状态如何，一律恢复为草稿、题目待审核，清空审核/发布时间，防止绕过复核。
- 共享快照不含 bank_events；需要完整历史恢复时应备份整个数据库。
- 原始 PDF 页码与坐标、OCR、图形化管理后台和用户权限系统不在本次范围。
